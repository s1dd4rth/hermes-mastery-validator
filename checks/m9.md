## Step 1 probe results (2026-05-28)

**Goal:** determine whether `hermes profile create` exists and what directory structure it produces.

**Probe:**

```bash
hermes profile --help
hermes profile create writer --clone
ls ~/.hermes/profiles/writer/
```

**Findings:**

- `hermes profile create` is a real, supported command in v0.12.0. Subcommands: `list`, `use`, `create`, `delete`, `show`, `alias`, `rename`, `export`, `import`.
- `hermes profile create writer --clone` created a profile at `/Users/siddarth/.hermes/profiles/writer`.
- Directory layout produced by `--clone`:
  ```
  ~/.hermes/profiles/writer/
    config.yaml
    cron/
    home/
    logs/
    memories/
    plans/
    sessions/
    skills/
    skins/
    SOUL.md          ← cloned from default profile (byte-identical at creation time)
    workspace/
  ```
- The cloned SOUL.md is byte-identical to the root SOUL.md immediately after creation. The validator detects this and tells the learner to edit it.
- `hermes -p writer` is **not** a valid flag — the correct invocation for a named profile is via its alias wrapper (e.g., the `writer` binary placed at `~/.local/bin/writer`).

**Acknowledged gap (spec §10 item 14):** Cross-profile delegation — root Hermes invoking the writer profile and receiving back a draft — is **unknown** in Hermes v0.12.0. No CLI surface for cross-agent RPC was found. M9 treats profiles as isolated specialist agents. If delegation surfaces in a later Hermes version, M9 will grow a `cross-profile-comms` manual. The curriculum states this honestly in the M9 learn text (Phase 1).

### `writer-soul-distinct-files`

**How:** SHA-256 hash comparison between `~/.hermes/profiles/writer/SOUL.md` and `~/.hermes/SOUL.md`.

```js
const writerHash = createHash('sha256').update(writerContent).digest('hex');
const rootHash   = createHash('sha256').update(rootContent).digest('hex');
if (writerHash === rootHash) → FAIL
```

**Rationale:** `--clone` copies the root SOUL.md byte-for-byte. A freshly cloned profile will always fail this check until the learner edits the writer SOUL.md. The check proves *isolation* (the two files have diverged), not *quality* (whether the new voice is actually good). Quality is verified by the `writer-soul-distinct-content` manual.

**Symlink case:** a symlink to root would have the same hash AND the same bytes, so it is caught by the hash comparison. Hashes differing is sufficient proof the files are distinct — no symlink walk is needed.

**Dev-box result (2026-05-28):** FAIL — cloned but not yet edited. Both files are 537 bytes with identical SHA-256. This is the correct instructional FAIL: the learner must edit `~/.hermes/profiles/writer/SOUL.md` to complete Phase 3.

**FAIL fix:** Edit `~/.hermes/profiles/writer/SOUL.md` and give the writer profile a genuinely distinct long-form-writing voice. Not just a one-line change — the `writer-soul-distinct-content` manual checks quality.

## Manual checks (2)

### `writer-soul-distinct-content`

**Instruction:** Read your writer profile's SOUL.md voice section; confirm it gives specific long-form guidance materially different from your root SOUL.md (not just a copy with one line changed).

**Rationale:** the SHA-256 check (`writer-soul-distinct-files`) proves the files are technically distinct. This manual check proves the *content* is meaningfully different — that the writer profile has a genuine long-form writing voice rather than a superficial rename. Think: paragraph rhythm, preferred sentence structures, style rules, tone for long-form vs. conversational.

**How to run:**
1. Read `~/.hermes/profiles/writer/SOUL.md` (especially any "voice", "tone", or "writing style" section).
2. Read `~/.hermes/SOUL.md` for the same sections.
3. Confirm: the writer SOUL.md contains specific long-form writing guidance that does NOT appear in the root SOUL.md, and is NOT just the root with minor cosmetic changes.

---

### `profile-delegation`

**Instruction:** Open your writer profile (via its alias wrapper — type `writer` in a new session or `hermes profile use writer`) and ask for a 500-word draft on the same topic you'd ask your root Hermes. Compare both drafts; confirm the writer's draft has a distinct voice.

**Rationale:** this closes the behavioral loop — proving that the SOUL.md edits actually change output, not just the file on disk. A profile that produces identical output to the root profile is not a specialist agent, it is a clone.

**How to run:**
1. Pick a topic (e.g., "Write a 500-word essay on the benefits of deliberate practice").
2. Ask your root Hermes agent for a 500-word draft.
3. Switch to the writer profile: run the `writer` alias wrapper, or `hermes profile use writer` + start a new session.
4. Ask the writer profile for a 500-word draft on the same topic.
5. Compare: Does the writer draft feel stylistically different? Different sentence length, rhythm, vocabulary, or structure? That is a PASS. Identical text = FAIL — edit SOUL.md further.

---

## Acknowledged gap: cross-profile delegation

Per spec §10 item 14: the OpenClaw M9 curriculum includes cross-agent-comms (root agent invoking a specialist profile and receiving back a structured response). The Hermes equivalent (if any) is **unknown** in v0.12.0.

`hermes -p <profile>` is not a valid flag. Profiles are invoked via their alias wrappers or `hermes profile use`. No CLI surface for cross-profile RPC was found.

**Current state:** M9 treats profiles as isolated specialists — the learner must manually switch between them. If Hermes adds cross-profile delegation in a later version, M9 will gain a `cross-profile-comms` manual check.

**In the curriculum:** Phase 1 of the M9 web app learn text explicitly states this limitation so the learner is not surprised when their writer profile cannot call back to root Hermes.
