## Security posture (applies to every line of runModule8)

| Rule | Implementation |
|---|---|
| Never read auth.json | `statMode()` only — no `readFileSafe()` on OAuth files |
| Never log token values | `ya29.`, `1//`, `GOCSPX-` never appear in evidence |
| Scope detection only via source | Grep `google_api.py` and other non-credential `.py/.ts/.js/.json/.md` files |
| Credential files filtered | `filter(d => !/secret|token|credential|\.env/i.test(d.name))` |
| Stat-only evidence | `oauth-credentials-present` evidence includes `path` + `mode` only, with `note: 'stat only — file contents never read'` |

### `oauth-scopes-cover-mail-and-calendar`

**Strategy: skill-source-grep** — the only honest programmatic surface available.

Per Phase 0 finding: `hermes config get` does not exist. Grepping the token file (auth.json) for scope values is PROHIBITED (would require reading credential contents). The next best surface is the Gmail skill's hardcoded scope list in its Python source.

**How:**
1. Enumerate `~/.hermes/skills/<gmailFound>/` recursively with `readdirSync({ recursive: true })`.
2. Filter to `.py`, `.ts`, `.js`, `.json`, `.md` files whose names do NOT match `secret|token|credential|\.env`.
3. Concatenate all content into `gmailScopesText`.
4. Test:
   - Gmail scope: `/gmail\.(send|readonly|modify|labels)|googleapis.*gmail|mail\.google/i`
   - Calendar scope: `/calendar\.(events|readonly|acls)|googleapis.*calendar|auth\/calendar(?!\.)/i`
5. Both matched → PASS. One matched → FAIL. Neither → MANUAL (downgrade — not enough signal).

**Node 21+ note:** `readdirSync` recursive entries use `f.parentPath` (not `f.path`). The validator handles both: `f.parentPath || f.path || gmailSkillDir`.

**Honest limitations:**
- This checks that the skill is _written_ to request the right scopes — not that the user's OAuth grant actually includes them.
- If the user ran the OAuth flow with `--services email` only (no `calendar`), the scope strings would still be present in source but the actual grant would be narrower.
- For full assurance: check Google Cloud Console > Credentials > your OAuth token > Scopes granted.
- The `calendar-event-read` manual below is the real behavioral proof that Calendar access works.

**Dev-box result (2026-05-28):** PASS — both scope families detected in `scripts/google_api.py`.

**FAIL fix:** Re-run the OAuth flow with both Gmail and Calendar services: `gws --auth-url --services email,calendar`.

**MANUAL (downgrade condition):** no scope strings detected in skill source (skill uses a different structure). Fall back to Google Cloud Console inspection — NEVER paste token values into chat.

## Manual checks (3)

### `test-email-sent-and-observable`

**Instruction:** Send a test email to yourself via the Gmail skill. Then ask the agent to scan your Gmail Sent folder for the message. Confirm BOTH:
- (a) The email arrived in your **inbox**
- (b) The email appears in your **Gmail Sent folder**

**Rationale:** Inbox-only confirmation is insufficient. Replay attacks, local mail forwarding, or server-side rules could deliver a message to the inbox without the agent actually initiating a send. Sent-folder observability closes the loop — an email appears in Sent only if the Gmail API's `messages.send` call was actually made under your OAuth grant.

**How to run:**
1. Ask your Claw: "Send a test email to me (your own address) with subject 'Hermes M8 test'."
2. After the approval prompt (if the outbound-approval-rule is in SOUL.md), confirm the send.
3. Ask your Claw: "Check my Gmail Sent folder and tell me if there's a message with subject 'Hermes M8 test' sent in the last 5 minutes."
4. Also verify in Gmail (browser or app) that the email is in the Sent folder.

### `approval-gate-works`

**Instruction:** Attempt to send an email and explicitly cancel at the approval prompt. Then scan Gmail Sent to confirm nothing was sent.

**Rationale:** "Email never arrived in inbox" is not proof the email was never sent — Gmail filtering, rules, or timing could delay inbox delivery. The Sent-folder check is what proves the Gmail API send call was never made.

**How to run:**
1. Ask your Claw: "Send an email to [any address] with subject 'M8 gate test'."
2. At the approval prompt, explicitly cancel: "Actually, cancel — don't send it."
3. Ask your Claw: "Check my Gmail Sent folder for any message with subject 'M8 gate test' in the last 10 minutes."
4. Confirm: NO such message in Sent.

**If the agent sends without asking for approval:** the `outbound-approval-rule` in SOUL.md is either absent or on the wrong surface. Fix: (a) add/update the rule in SOUL.md, (b) start a fresh session, (c) retry. If still fails after fresh session, SOUL.md may not be consulted at tool-call time — escalate as a §10 finding.
