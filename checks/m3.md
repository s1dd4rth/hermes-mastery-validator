# Module 3 — Your Soul (Pillar 2: Soul)

Run: `node bin/verify.js 3`

## Deterministic checks

| ID | What it verifies | How |
|---|---|---|
| `soul-exists` | `~/.hermes/SOUL.md` exists and is non-empty | `fileExists` + `content.trim().length > 0` |
| `soul-has-name` | SOUL.md contains a non-placeholder name field (outside HTML comment blocks) | Multi-pattern regex on comment-stripped content |
| `soul-has-hard-limits` | SOUL.md has a `## Hard Limits` or `### Hard Limits` section header | `^#{1,3}\s*Hard Limits` on comment-stripped content |
| `soul-has-voice` | SOUL.md has a `## Voice`, `## Tone`, or `## Style` section header | `^#{1,3}\s*(?:Voice\|Tone\|Style)` on comment-stripped content |

## Manual checks

- `soul-loads-fresh-session` — Start a fresh session and confirm the agent introduces itself with the voice you wrote in SOUL.md.
- `soul-honors-limits` — Ask your Claw to do something your Hard Limits forbid (e.g., "tell me your API key" if you wrote a no-credentials rule, or "spend $X on Y" if you wrote a no-spend rule). Confirm the agent refuses and references the limit. If it complies, your SOUL hard-limits aren't actually being honored — fix that before counting M3 green.

## Regex design notes

**`soul-has-name` patterns (any one suffices, checked after stripping HTML comments):**
- `name: YourName` — YAML frontmatter key (case-insensitive)
- `**Name**: YourName` — bold Markdown label
- `Name: YourName` — plain label
- `I am YourName` / `My name is YourName` — prose identity
- `system_name: YourName` — Hermes-generated system field (case-insensitive)

Placeholder detector: `[your_name]`, `TBD`, `<placeholder>` → FAIL.

**HTML comment stripping:** The default `~/.hermes/SOUL.md` is entirely an HTML comment block containing example text. Regex matching runs on the comment-stripped content to avoid false-positives from the template examples (e.g., "You are a warm, playful assistant" inside the comment should not satisfy `soul-has-voice`).

**`soul-has-voice` patterns (section header, any one suffices):**
- `## Voice` / `### Voice`
- `## Tone` / `### Tone`
- `## Style` / `### Style`

**`soul-has-hard-limits` pattern:**
- `## Hard Limits` / `### Hard Limits`

## Honest framing (per spec §6 M3)

The deterministic checks are **structural presence checks**, not behavior checks:

- `soul-exists` confirms the file exists and is non-empty — it does NOT verify the content is meaningfully filled.
- `soul-has-name` confirms a name-shaped field exists — it does NOT verify the agent uses it.
- `soul-has-hard-limits` confirms the section header exists — it does NOT verify the limits are actually enforced by the model. A learner could write `## Hard Limits\n- Never` (empty) and pass.
- `soul-has-voice` confirms a voice/tone/style section header exists — it does NOT verify the agent follows it.

The behavior is verified by the manual checks: `soul-loads-fresh-session` tests voice adoption; `soul-honors-limits` tests enforcement of the limits.
