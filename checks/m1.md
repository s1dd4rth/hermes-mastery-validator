# Module 1 — Install & Foundation

Run: `node bin/verify.js 1`

## Deterministic checks

| ID | What it verifies | How |
|---|---|---|
| `hermes-installed` | `hermes --version` succeeds | `runCmd('hermes', ['--version'])` |
| `skill-registered` | `hermes skills list` includes `hermes-mastery-validator` | `runCmd('hermes', ['skills', 'list'])` |
| `model-configured` | Config key `model.provider` is set | `readYamlValue('~/.hermes/config.yaml', 'model.provider')` |
| `validator-skill-installed` | `~/.hermes/skills/hermes-mastery-validator/SKILL.md` is present | `fileExists` |

## Manual checks
None — M1 is fully deterministic.

## Notes
- `model.provider` is read via `readYamlValue` (js-yaml-based), NOT `hermes config get`. Confirmed against Hermes v0.15.1 (`hermes config show` → `Model: {'default': 'gemini-2.5-pro', 'provider': 'google', ...}`).
- **Install method**: Hub install is unsupported — `hermes skills install s1dd4rth/hermes-mastery-validator` fails with "Could not fetch from any source" (v0.15.1), and the validator needs its whole repo (bin/, checks/, node_modules), not a single SKILL.md. Clone + symlink is canonical: `cd ~ && git clone https://github.com/s1dd4rth/hermes-mastery-validator.git && ln -sfn ~/hermes-mastery-validator ~/.hermes/skills/hermes-mastery-validator && cd ~/hermes-mastery-validator && npm install`.
- **`skill-registered` replaces the old `gateway-running` check.** There is no Hermes web dashboard on :1919 — that was an OpenClaw assumption. In Hermes, `hermes gateway` connects messaging channels (Telegram/Discord/…) and skills run inside a `hermes`/`hermes --tui` session, not behind a gateway. The real prerequisite for this validator is that Hermes recognizes the installed skill, which `hermes skills list` enumerates.
