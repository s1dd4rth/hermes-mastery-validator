# Module 1 — Install & Foundation

Run: `node bin/verify.js 1`

## Deterministic checks

| ID | What it verifies | How |
|---|---|---|
| `hermes-installed` | `hermes --version` succeeds | `runCmd('hermes', ['--version'])` |
| `gateway-running` | Dashboard reachable at 127.0.0.1:1919 | `httpProbe` |
| `model-configured` | Config key `model.provider` is set | `readYamlValue('~/.hermes/config.yaml', 'model.provider')` |
| `validator-skill-installed` | `~/.hermes/skills/hermes-mastery-validator/SKILL.md` is present | `fileExists` |

## Manual checks
None — M1 is fully deterministic once the §10 M1-blocking items resolve (resolved in Phase 0 commits 17cd5f0–f5644e3).

## Notes
- Per Phase 0 finding (commit 0f47957), `model.provider` is read via `readYamlValue` (js-yaml-based), NOT `hermes config get` — that subcommand does not exist in Hermes v0.12.0.
- Per Phase 0 finding (commit 5e5bb08), the dev workflow uses a symlink rather than `hermes skills install /local-path` (unsupported). Course authors: `ln -sfn $(pwd) ~/.hermes/skills/hermes-mastery-validator`. Learners: `hermes skills install s1dd4rth/hermes-mastery-validator`.
- **Dashboard port deviation**: The spec assumed port 1919. Phase 0 live probe (2026-05-27) found no Hermes gateway process listening on any port — port 1919 did not respond. The config has a `dashboard:` section with only `server_actions: ''` (no port key). The `gateway-running` check uses port 1919 per spec and emits an honest FAIL when the gateway is not running; it will emit PASS once the gateway is started and responds on that port.
