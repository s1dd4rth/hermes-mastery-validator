# Module 2 — Your Memory (Pillar 1: Memory)

Run: `node bin/verify.js 2`

## Deterministic checks

| ID | What it verifies | How |
|---|---|---|
| `user-md-exists` | `~/.hermes/memories/USER.md` exists, non-empty, has a real identity/name field (not placeholder). Char limit 1375 informational. | `fileExists` + multi-pattern regex |
| `memory-md-exists` | `~/.hermes/memories/MEMORY.md` exists, non-empty, contains at least one project/context entry. Char limit 2200 informational. | `fileExists` + entry-pattern regex |

## Manual check

- `memory-conversational` — Tell the agent a new fact in chat (e.g., "remember that I prefer terse responses" or "chuck that in memory: I drink oat milk"), ask it to remember, then read USER.md or MEMORY.md and confirm the agent wrote it. This is the load-bearing check; the deterministic checks above only confirm files exist with the right shape.

## Regex design notes

**`user-md-exists` name patterns (any one suffices):**
- `Name: Alice` / `**Name**: Alice` — structured YAML-ish field
- `System username is alice` / `username is alice` — Hermes-generated header format
- `I am Alice` / `My name is Alice` — prose identity

Placeholder detector: `[your_name]`, `TBD`, `<placeholder>` → FAIL.

**`memory-md-exists` context patterns (any one suffices):**
- `- item` or `* item` — bullet entry
- `working on` — active work prose
- `project:` — explicit project marker
- `uses \`toolname\`` — Hermes standard tool-reference sentence
- `installed at /path` — tool installation record
- backtick-quoted identifier (e.g., `` `gbrain` ``) — named tool reference

Rationale: Hermes writes natural sentences into MEMORY.md ("User uses `gbrain`..."), not just structured bullets. The regex accepts both forms.

## Honest framing (per spec §6 M2)

The deterministic checks are formatting checks, not memory-loop checks. A learner could hand-write placeholder-shaped content and pass. The conversational round-trip in the manual (`memory-conversational`) is what proves Hermes's memory pillar actually works.
